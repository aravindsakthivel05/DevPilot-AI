# Repository-answer quality improvements — October 4, 2026

DevPilot now separates finding a source, reading an implementation, generating a claim, and checking that claim. A citation or a model review is still not proof of correctness. The final benchmark and manual source review are recorded in `evaluation/quality-2026-10-04/`.

## Changes

- Repeated unnamed Rust and C++ parameters receive distinct identifiers. Go calls through an explicitly declared own receiver can resolve; dynamic receivers remain unresolved.
- Header content selects the C++ grammar when appropriate. C/C++ macro definitions retain nearby conditional guards; DevPilot does not expand macros or infer the active build configuration.
- Adjacent API documentation participates in search without moving executable source coordinates. C# test projects are recognized correctly. English stemming and explicit snake/camel-case identifiers improve query matching. Each aspect retains caller-supplied scope, and recognizable coordinated subjects get separate obligations.
- Nomic queries and documents receive their respective task prefixes. Dense candidates use compact identities, documentation, and implementation head/tail excerpts. Full source, parameters, and type references remain stored and searchable. Readiness reports dense coverage against eligible entities rather than all records.
- Structural rebuilds reuse only unchanged identities, signatures, source and documentation with compatible vectors. Readiness filters the actual configured embedding model. Parser, search and embedding revisions invalidate incompatible derived data. Ingestion and readiness use the current shared index version.
- A bounded model step selects source definitions to read. A source reader follows candidate helpers, JavaScript call wrappers, Rust generic calls, paired ordinary/fallible APIs and referenced global defaults. Candidate reads are explicitly distinguished from proven dispatch relationships.
- Generation allocates source space to primary definitions and relevant helpers. Citations keep original file coordinates. Supported and missing claims can coexist within an aspect; valid individual claims survive rejection of another claim.
- The separate claim reviewer receives exact cited lines and additional surrounding code without duplicating already cited context. Short review reasons reduce output overhead. An optional separate reviewer model can be configured.
- Necessary-support guards reject certain unsupported absence, type-contrast and failure-baseline and preprocessor value-versus-definedness claims, unsupported explicit identifiers and a narrowly recognized captured-getter cache contradiction. These are conservative checks, not a general semantic verifier.
- An accepted partial draft can optionally receive one correction pass (`DEVPILOT_REPAIR_REJECTED_CLAIMS=1`) using rejected-claim feedback and the same source. The existing two-attempt limit remains. Failure or worse supported-aspect coverage preserves the earlier draft. This adds latency and is not independent factual verification. It remains disabled by default after mixed pilot results; model-reviewed aspect coverage does not establish better semantics.
- The same reading and claim pipeline applies to direct RAG and optional LangGraph answers. The frontend labels partial coverage clearly.

## Model and optional reranking

Normal local inference remains Qwen2.5-Coder 14B. Qwen3.5 9B was downloaded and tested locally as a candidate, but its preliminary diagnostic and smoke outputs did not establish better answer quality. Those runs are retained as diagnostics, not presented as final benchmark accuracy. A further generation-only thinking diagnostic also failed to establish better completeness; it was not promoted.

A pretrained local cross-encoder is available through the `reranking` extra and `DEVPILOT_NEURAL_RERANKER`. It reduced source coverage in this development benchmark, so it remains disabled by default. Enabling a pretrained model is not fine-tuning it.

```sh
python -m pip install '.[reranking]'
DEVPILOT_NEURAL_RERANKER=cross-encoder/ms-marco-MiniLM-L6-v2 ./setup_and_run.sh
```

Benchmark it on your questions before enabling it. Its weights may download on first use. Repository inference stays local with the configured Ollama URLs.

## Reproduce

The original five repositories and question wording remain pinned in the benchmark snapshots and questions files. Expected answers and source labels are used for scoring after retrieval; they are not supplied to source selection or answer generation.

```sh
export DEVPILOT_DATA="$PWD/.devpilot/quality-2026-10-04"
export DEVPILOT_LLM_BASE_URL=http://127.0.0.1:11434/v1
export DEVPILOT_LLM_MODEL=qwen2.5-coder:14b
export DEVPILOT_EMBEDDING_MODEL=nomic-embed-text:latest
export DEVPILOT_PROVIDER_TIMEOUT_SECONDS=180
python -m scripts.evaluate_source_coverage evaluation/quality-2026-10-04
python -m scripts.test_new_repositories run --output evaluation/quality-2026-10-04 --split development
```

The answer runner refuses to resume results after questions or backend code change. Source-span coverage is not answer correctness. The five repositories guided development and are not an untouched holdout. ItsDangerous and Zod have separate questions, snapshots and results under `evaluation/quality-holdout-2026-10-04/`; questions were frozen before their answer outputs. Zod’s cache failure subsequently informed a general guard, so Zod is a development repository for future comparisons; its original pre-change holdout result is retained unchanged.

## Learning and limits

No model weights were trained from unverified answers. Existing review queues and exports remain intact. New failed questions should enter that reviewed learning loop with source ranges, correct answers and failure categories. Local fine-tuning remains gated on a sufficiently large reviewed corpus and separate repository holdouts; the earlier ineffective experimental adapter remains unused.

Codex-authored source reviews are not independent human labels. This small benchmark cannot establish correctness on every repository. Dynamic dispatch, compiler-dependent behavior, excluded/generated files and live runtime state still need other evidence. The local application retains old snapshots and marks older derived indexes for rebuilding.
