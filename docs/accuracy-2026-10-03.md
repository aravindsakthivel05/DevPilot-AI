# Accuracy and verification checkpoint — October 3, 2026

DevPilot now validates original source coordinates and named owners, reports incomplete question
aspects, uses persistent search candidates, and checks generated repairs against selected existing
tests. These are reliability improvements, not a guarantee of correct answers or complete repository
understanding. Raw results and provenance are under `evaluation/accuracy-2026-10-03/`.

## Implemented behavior

| Area | Change | Boundary |
| --- | --- | --- |
| Evidence | Original file-line maps, contiguous citation ranges, owner validation and declared Python public reexports | Identity and line existence do not prove a claim |
| Answers | Structured claims for every aspect; explicit missing evidence; bounded retry with broader evidence | Missing aspects can remain unanswered |
| Claim review | Separate model call receives each claim's cited lines only; rejected aspects become incomplete | Same model can make correlated mistakes; not independent human review |
| LangGraph | Up to six aspects, two focused rounds, outgoing helpers and bounded supplemental evidence | Candidate coverage is a retrieval heuristic |
| Context | Source windows selected around aspect-specific code, stable line numbers, explicit 8192 local context | Byte-based token planning is an estimate; excerpts can omit relevant control flow |
| Search | SQLite FTS5, repository-local BM25 reranking and revision-aware metadata cache | Static and semantic retrieval still miss important helpers |
| Index | Complete document chunks, decorators/aliases, conservative Java parent/import/declared receiver resolution | Other languages remain searchable text; ambiguous overloads and runtime dispatch stay unresolved |
| Embeddings | Complete batches, provider/model/revision signature, dimensional and coverage checks | Pin a revision to detect changes behind mutable model tags; no broad accuracy benefit established |
| Verification | Four guided stages with structured testcase identities and selected existing-suite preservation | Synthetic fixtures and selected tests do not establish real-issue repair success |
| UI/runtime | Aspect status, exact model excerpts, structured counts and explicit readiness probes | A configured provider is not a successful readiness check |
| Learning | Source-backed review packs, reviewed-target export gate and repository-separated validation/holdout | No new model weights trained; unverified answers never become automatic truth |

## Repeated public-repository questions

The same FastAPI, Django and PyTorch questions were replayed in Quick and Deep modes with Qwen 7B.
This checkpoint preceded the final returned-call excerpt fix; these six answers were not replayed
after that narrowly targeted context change.
Mean labelled-symbol recall@8 moved from 66.7% in the saved baseline to 70.8% in this run. Five of
six runs produced accepted structured model output; four were reported partial and one fell back
to evidence-only after validation rejection. **Source review found zero correct and complete
answers across these six runs.** The FastAPI Quick answer incorrectly equated route registration
with OpenAPI schema assembly; several PyTorch citations still referenced registration/initialization
instead of invocation. Other answers provided useful fragments but omitted required steps.

This is evidence of remaining answer-quality failures, not a successful overall accuracy score.
The model audit missed some unsupported claims. The safeguards and improved ranking should not be
represented as proven factual-answer improvement. See [raw reruns](../evaluation/accuracy-2026-10-03/public-three-final.json)
and [source review](../evaluation/accuracy-2026-10-03/public-three-source-review.json).

## Frozen local model comparison

Jinja and Gson were pinned as new evaluation-only repositories before this comparison. Each model
received the same bounded source excerpts for six answerable questions and two explicit live/private
runtime questions. One attempt per question was used; end-to-end retry is measured separately.
This frozen checkpoint preceded the final returned-call/field-name fixes found on the Pydantic
development questions. The Jinja/Gson comparison was not repeated for tuning those fixes.

| Model | Correct and complete answers / 6 | Correct, complete and strict citation support / 6 | Rejected attempts | Median answerable-case time |
| --- | ---: | ---: | ---: | ---: |
| Qwen2.5-Coder 7B | 1 | 1 | 1 | 23.1 seconds |
| Qwen2.5-Coder 14B | 3 | 2 | 1 | 81.3 seconds |

Both declined the two live/private questions without a model call. Source review found an inverted
async condition in 7B's Jinja answer, an overly broad strictness fallback in its Gson answer, and
unsupported publication claims in both models' adapter explanations. 14B's writer behavior was
correct, but its exact restoration citations omitted the `finally` header. These accepted answers
demonstrate that the model audit still misses errors. No claim of hallucination-free answering or
broad generalization follows from this small, single-repeat set. Judgments are Codex manual source
review, not independent human grading.

14B ran entirely on the GPU with an 8192-token context, using 9.5 GB of loaded-model memory as
reported by Ollama on this 18 GiB Mac. It is installed as an accuracy option; the setup script retains
7B for lower latency. To try 14B, set `DEVPILOT_LLM_MODEL=qwen2.5-coder:14b` before starting the
backend. Review answers against their sources with either model.

See the [raw comparison](../evaluation/accuracy-2026-10-03/new-holdout-model-comparison-final.json),
[source judgments](../evaluation/accuracy-2026-10-03/model-source-review.json), and
[runtime configuration](../evaluation/accuracy-2026-10-03/model-runtime-14b.txt).

## Final serialization regression

The Pydantic replay exposed two actual implementation defects: selected argument lines could omit
their returned callee, and a real instance-field call could be falsely rejected when its `self.`
prefix was omitted in the answer. Excerpts now reserve returned calls and requested keyword values;
identity checks accept the exact declared field spelling after `self`, `cls` or `this` without
accepting a different owner/field. Both have behavioral regression tests.

With the same serialization question and final evidence, both 7B and 14B identified
`__pydantic_serializer__.to_python()` and the direct `exclude_none` forwarding. The single-attempt
times were 41.9 seconds and 82.0 seconds. This validates that specific fix, not broad accuracy.
[Final comparison](../evaluation/accuracy-2026-10-03/pydantic-serialization-final.json).
The earlier full three-question Pydantic replays are retained under `diagnostics/`; schema/rebuild
questions still have rejection or factual-support failures and were not all revalidated after the
last field-name fix.

## Reproduce and inspect

```sh
python -m pytest -q
ruff check backend tests scripts
ruff format --check backend tests scripts
cd frontend && npm run format:check && npm run build
```

The real Docker test requires its prepared image and a running engine; without them it is skipped.
To rerun answer checks, configure the local provider as in `.env.example` and choose a new output
path; evaluation scripts refuse to overwrite retained reports.

```sh
.venv/bin/python -m scripts.test_public_repository_tiers --output /tmp/devpilot-public-three.json
.venv/bin/python -m scripts.replay_question_report evaluation/pydantic-devpilot-question-run-v14.json --output /tmp/devpilot-pydantic.json
.venv/bin/python -m scripts.compare_local_models qwen2.5-coder:7b qwen2.5-coder:14b --dataset evaluation/accuracy-2026-10-03/new-holdout-cases.jsonl --manifest evaluation/accuracy-2026-10-03/new-holdout-snapshots.json --cases 8 --repeats 1 --output /tmp/devpilot-model-comparison.json
```

The local comparison uses one generation attempt per case on identical frozen context; it isolates
model behavior and does not exercise the end-to-end retry policy. Source ranges distinguish Gson
method overloads. Labels and answer judgments in this pass are Codex source reviews, not independent
human grading. One repeat and a small sample cannot establish a generally superior model.
